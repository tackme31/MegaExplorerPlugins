# WD Tag Search — 仕様と決定事項

**状態: 0.2.0（検索をプラグイン内で行い、結果をサムネイルのグリッドで出すようにした。§10）。** WD Tagger（`wdtagger_plugin`）のタグを対象に、アカウントに実際に付いているタグからのサジェスト
（入力欄の下に出るドロップダウン）と、ヒット件数の即時表示を見ながら `tag:` 条件を組み立て、Search ボタンで
**起動時に読んだ一覧をメモリ上で照合し、当たったファイルをサムネイルのグリッドに新しい順で並べる**。
同じクエリをアプリの表示中のタブで検索させる「Search in MEGA Explorer」ボタンも残している（本体の `ui.search`、§6）。

当初は汎用のタグ検索を考えていたが、`wd:` / `chara:` / `rating:` の扱いが WD Tagger の保存形式に依存するので
WD Tagger 専用とした。名前は WD Tag Search（`wdtagsearch_plugin`、`com.takumi.wdtagsearch`）。
検索の実行をやめてクエリ作りに絞った時期は WD Tag Query Builder と呼んでいたが、本体の `ui.search` で検索を
実行するようになった（§6）ので、検索の道具としての名前に戻した。

## 1. 前提: アプリの検索の仕様（MEGA Explorer 本体）

- 検索欄の `tag:語` はタグ検索。`tag:"空白入り"` も書ける。複数書くと **AND**。**OR・NOT は無い**。
- 照合は **大文字小文字を区別しない部分一致**。「すべての語が、そのアイテムのどれかのタグに部分文字列として
  含まれる」で当たる。`tag:solo` は `solo_focus` にも、`tag:general` は `rating:general` にも当たる。
- 検索は **開いているフォルダを起点に、サブフォルダまで** 探す。検索ポップアップの「このフォルダのみ」は
  直下だけに絞る別のオプション。
- 結果にはタグの付いた **フォルダも** 含まれる。

## 2. タグの出どころと語の分け方

- サジェストに使うのは **アイテムに実際に付いているタグだけ**。WD Tagger のタグ一覧 CSV（`selected_tags.csv`）は
  使わない。0 件になるタグを出さずに済み、手で付けたタグも同じ扱いで出せる。
- 集計は起動時に、クラウドドライブのルートから `items.descendants`（`type: "file"`, `fields: ["tags", "path"]`）
  を全ページ読んで行う。アプリのメモリ上の読み取りなので MEGA への通信は無い。集計は別スレッドで行い、
  ウィンドウはすぐ開く。
- WD Tagger は MEGA のタグ 1 個に複数の語をまとめて保存している（`wdtagger_plugin/docs/SPEC.md`）。
  サジェストは **語単位** に分ける:

| 保存されているタグ | 分け方 | クエリに入る語 | 候補の表示 |
| --- | --- | --- | --- |
| `wd:1girl solo long_hair` | `wd:` を外して空白で分割 | `solo` | `solo` |
| `chara:hatsune_miku chara:kagamine_rin` | 空白で分割、`chara:` は残す | `chara:hatsune_miku` | `hatsune_miku [chara]` |
| `rating:general` | サジェストに出さない（§3） | `rating:general` | — |
| それ以外（手で付けたタグ） | 分けない | タグそのまま | `mytag [tag]` |

- 候補から外すもの: 名前が空の語（`wd:` や `chara:` だけのタグ）と、`"` を含む語（§8）。
- 語の同一視は小文字化で行い、表示には最も多い表記を使う。候補の順は「入力と完全一致 → 前方一致 → 件数の多い順」。
- 候補に添える件数は「その語を持つファイル数」（語単位の完全一致）。クエリとしてのヒット件数（§4）とは別物。

## 3. rating はドロップダウン（All / general / sensitive / questionable / explicit）

最初はチェックボックスにしたが、検索に OR が無いため 2〜3 個の組み合わせをクエリで表せない。そこで
**1 つだけ選ぶ** ドロップダウンにした。All は絞り込みなし、それ以外は `tag:rating:<値>` をクエリに足す。
各項目には、クラウドドライブ全体でのファイル数を添える。

rating も **ほかの語と同じ規則（部分一致、どれかのタグに当たれば可）で数える**。「ファイルの rating を 1 つ取り出して
完全一致で比べる」作りにすると、rating タグが 2 つあるファイルや `rating:generalx` のような値で、アプリの検索結果と
件数がずれるため。

## 4. ヒット件数

- 語の分割とは関係なく、**保存されているタグ文字列そのものにアプリと同じ規則（§1）を当てて** 数える。
  したがって部分一致による「余計な当たり」も含めて、アプリの検索結果と一致する（ファイルに限れば）。
- 数えるのは **ファイルだけ**。WD Tagger はフォルダにタグを付けないので、普段は差が出ない。
- 件数は **起動時点** のもの。開いている間に付いたタグは反映されない（開き直せば数え直す）。
- 件数は **クラウドドライブ全体** での数で、グリッドに出る結果（§10）と常に一致する。アプリの検索は開いている
  フォルダを起点にする（§1）ので、Search in MEGA Explorer をルート以外で使うと、結果は件数以下になる。

## 5. 検索範囲の指定は持たない

一時期、開いたフォルダのパスを表示し「このフォルダ以下 / すべて」を選んで件数を絞れるようにしていた。検索は
アプリの表示中のタブ（そのとき開いているフォルダ）で走るので、どこで検索するかはユーザーがアプリ側で決める
（§6）。範囲の選択は意味を失い、外した。コンテキストメニューの情報は、ルートを見つける起点にしか使わない。

範囲を絞る設定は §11 で別に入った。これはウィンドウ上の選択ではなく、一覧の量そのものを減らすためのもの。

## 6. Search in MEGA Explorer は本体の `ui.search` で表示中のタブに走らせる

（0.1.0 では、これが唯一の検索だった。0.2.0 で主な検索はプラグイン内に移した。§10）

当初は `ui.search {query, folder?}`（指定フォルダを開いて検索する）を考えたが、検索の状態がタブごとにあり移動で
消えるアプリの作りのせいで、起点・タブ・既存フィルタの扱いなど決めることが多く、一度見送ってコピー＆貼り付けにした。

その後、本体の `ui.search` を「表示中のタブで、ユーザーが入力したのと同じように検索する」と定義し直して実装した
（本体 `docs/investigations/STUDY_PLUGIN_API_EXTENSIONS.md` §H）。フォルダもタブも指定しないので、上の論点は消えた。
Search in MEGA Explorer ボタンはクエリ欄の文字列をそのまま `ctx.search(query)` に渡す。

- 欄は普通の入力欄なので、手で直してから検索できる。
- `ui.search` は検索の条件をまるごと置き換えるので、アプリの検索ポップアップのフィルタ（種類・カテゴリ等）は
  既定値に戻る。件数（§4）もフィルタ無しで数えているので、これで揃う。
- 検索は呼んだ時点の表示中のタブで走る。ウィンドウを開いたあとにアプリでフォルダやタブを移っていれば、そちらで走る。
- `ui.search` の無い古いアプリでは、呼び出しがエラーになり、その旨を状態欄に出す。

## 7. クエリ文字列の組み立て

- アプリの構文解析は **半角スペース・タブ・全角スペース（U+3000）** で語を区切る。このどれかを含む語は
  `tag:"..."` と引用符で囲む。
- 構文に `"` を書く方法は無い（エスケープなし）。`"` を含む語は正しく検索できないので候補に出さない。
  Shift+Enter で手入力した語からは `"` を取り除き、件数もその語で数える。

## 8. 不正な値への耐性

ユーザーが手で `wd:xxx` のようなタグを付けると集計対象になるが、それ自体は問題としない。プラグインは `items.read`
しか持たない読み取り専用なので、どんな値でもアカウントは変わらない。空の値・連続空白・絵文字（tkinter で表示・入力とも
可）では落ちないことを確認した。件数やクエリがアプリの検索とずれるケースは §2・§3・§7 の対処で塞いだ。
残るのは大文字小文字の比較の差だけ: プラグインは Python の `lower()`、アプリは Qt の大文字小文字無視の比較と SDK の
タグ検索で、`İ` など一部の非 ASCII 文字で一致しないことがある。実害はほぼ無いので揃えない。

## 9. 未決定・今後の候補

- **完全一致の書き方**（本体）: danbooru タグは部分一致だと当たり過ぎる（`girl` → `1girl`）。`tag:=girl` のような構文の追加。
  `wd:` の語は 1 つのタグに空白区切りで入っているので、完全一致を入れるならタグ単位でなく語単位の照合が要る。
- **OR / NOT**（本体）: rating の複数選択や `-tag:rating:explicit` に必要。
- **集計の速さ**: 実データでは未計測。読むのは `tags` だけだが、本体は `fields` で絞ってもアイテムごとにルートまでの
  パスを計算している。遅ければ本体側で「`path` を求められていないときは計算しない」最適化を入れる。
- **再集計**: 今は開き直すしかない。必要ならボタンを足す。
- **起動場所**: 今はコンテキストメニュー（ファイル・フォルダ・フォルダの空き領域）からしか開けない。選択とは関係の無い
  機能なので、将来はコンテキストメニュー以外の場所（候補はアプリの More メニュー）から開けるようにする予定。
  本体側のプラグイン対応を広げる話なので、当面はコンテキストメニューのまま進める。

## 10. 検索結果はプラグイン内で求め、グリッドに出す（0.2.0）

`ui.search` 経由の検索は、本体が SDK のタグ検索でツリーを探すため、大きなアカウントでは遅かった。一方プラグインは
起動時にドライブ全体の `tags` を読み込み、件数（§4）をすでに即時に数えていた。そこで **件数と同じ照合で当たった
ファイルそのものを返し**、WD Similar と同じサムネイルのグリッドに出すことにした。検索は MEGA にも本体の検索にも
問い合わせない。

- 一覧で読む項目は `name`・`tags`・`mtime`・`hasThumbnail`。`path` は本体がアイテムごとにルートまで辿るので（§9）
  一覧では取らず、ツールチップを出すときに 1 件ずつ `items.get` で読んでキャッシュする。
- 並びは **更新日時の新しい順**。タグの一致にはスコアが無いので、新しく入れたものが先に見える順を選んだ。
  `mtime` の無いものは最後。
- グリッドは WD Similar の実装をコピーして、スコア表示や「似たものを探す」を外した。プラグインはフォルダごとに
  インストールされ共有モジュールを持てないので、コピーとし、以後は同期しない。
- サムネイルは表示中のタイル（1 ページ 40 件、Load more で追加）の分だけ、`items.fetchThumbnail` を 4 並列で取る
  （本体のサムネイル処理の並列数に合わせた。WD Similar と同じ）。権限 `content.read` が要る。
- ダブルクリックで本体のビューアで開き（`ui.open`）、右クリックからフォルダ上の場所を表示する（`ui.reveal`）。
- サジェストは常時表示の一覧をやめ、入力中だけ入力欄の下に浮かぶドロップダウンにした。tkinter に標準の
  オートコンプリートは無いので、枠なしの `Toplevel` と `Listbox` で作る。一覧をクリックすると入力欄からフォーカスが
  移るので、押した時点で確定し、フォーカスを入力欄に戻す。入力欄のフォーカスが外れたら 200 ms 後に閉じる。
- 語の入っていない入力欄で Enter を押すと検索する。語の追加（Enter）と検索の Enter を同じキーで続けて打てるように。

## 11. 一覧するフォルダを settings.json で絞る

既定はドライブ全体。プラグインフォルダ直下の `settings.json` の `"folders"` に複数のパスを書くと、その下だけを
`items.descendants` で読む。大きなドライブでの全件読み込みの待ち時間と、アプリが読んだアイテムを保持し続ける
メモリを減らすのが目的（§5 のウィンドウ上の範囲選択とは別物）。

- パスで書く。ハンドルは名前の変更に強いが、手で書く設定には向かない。API にパスからの引き当てがないので、
  ルートから `items.children` で一段ずつたどる。同名の兄弟フォルダはすべて対象にする。
- 見つからないパスは飛ばしてステータス行に出す。**ドライブ全体には戻さない**: 名前を変えただけで黙って全件
  読み込みに戻るのが、この設定で防ぎたいことそのものだから。全部見つからなければ何も読まずエラーにする。
- 別の指定の中にあるフォルダは落とす（二重に数えないため）。
- 件数とグリッドは指定フォルダ内だけになるが、Search in MEGA Explorer（§6）はアプリの表示中のタブで走るので、
  この設定は効かない。
- 設定はプラグインごとに持つ。`scope.py` は WD Similar のものを元にしたが、以後は同期しない。設定ファイルは gitignore
  してリリース zip に入れない。
