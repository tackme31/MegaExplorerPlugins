# Duplicate Finder 設計メモ

**状態（2026-10-04）: 0.1.0 実装済み。** 読み取り専用で、重複を一覧して MEGA Explorer で該当ファイルを
開くところまで。消す・動かすはアプリ側で行う。

## 判定

- **キーは `size` と `crc` の組。** `crc` は MEGA Explorer が Item に出す、MEGA の fingerprint の CRC 部分
  （アプリ側の決定は MegaExplorer の `docs/investigations/STUDY_PLUGIN_API_EXTENSIONS.md` §I）。
  fingerprint 全体は mtime を含むので使わない。
- **一致は「ほぼ確実」で証明ではない。** 8 KB を超えるファイルの CRC は全体から散らばった計 8 KB しか
  見ていない。中身の突き合わせ（`items.readRange`）は入れていない: 消す機能を持たない以上、最終判断は
  ユーザーがアプリ側でするため。README に明記している。
- **比べないもの**: 空ファイル（全部が同じ「中身」になり一覧が埋まる）と、`crc` が `null` のファイル
  （fingerprint 無しでアップロードされたもの）。どちらも件数だけ出す。
- **同じファイルを二度数えない。** 親子関係にあるフォルダを両方選ぶと `descendants` に同じハンドルが
  二度出るので、ハンドルで重複を除く。

## 範囲

- 右クリックしたフォルダ以下の全階層。複数選択なら合わせて比べる。フォルダ背景なら今のフォルダ、
  Cloud Drive ならドライブ全体（`when.targets: "folders"` がそのまま効く）。
- 読むのは `items.descendants`（`fields: name, size, path, crc`）だけで、MEGA へは通信しない。
  権限は `items.read` のみ。

## UI

- **ゴミ箱へ送る機能は持たない**（PoC 後の判断）。「Go to file」で `ui.reveal` すれば、アプリ側で
  普段どおり消す・動かす・中身を見るができ、プラグインに確認ダイアログや選び方の設計を持たせずに済む。
- **移動は明示的なボタン**: PoC はダブルクリックだけで、何が起きるか分かりにくかった。「Go to file」
  ボタン（ファイル行を選んだときだけ有効）を主にし、ダブルクリックと Enter は同じ動作の近道として残す。
  組の行のダブルクリックは Treeview 標準の開閉のまま。
- **並び**: 無駄な容量（`size × (件数 − 1)`）の大きい順。組の中はパス順。上部に合計を大きく出す。
- **一覧は開いた時点のもの。** 窓を開いたままアプリで消した・動かしたファイルも残る。再読み込みは
  付けていない（コマンドを実行し直せば済み、`ui.reveal` が消えたファイルで `-32002` を返したときは
  注記に出す）。
- 高 DPI: `SetProcessDpiAwareness(1)` で滲みを防ぎ、Treeview の行の高さと列幅を DPI で掛ける。
  ダークモードは未対応（ヘルパーが `initialize` の `app.colorScheme` を渡していない）。
